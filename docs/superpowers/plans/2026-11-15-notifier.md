# M365 DFIR Docs Notifier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions job that watches 115 Microsoft Learn pages and the M365 Roadmap RSS feed, and sends the user a phone push (ntfy) for forensically important doc changes, plus a Monday digest of the rest.

**Architecture:** A Python package `notifier/` runs every 3 hours. It fetches each page, normalizes the article body to Markdown, diffs it against a committed snapshot, sets a minimum level with deterministic rules, asks `claude-haiku-5-5` to classify, then pushes or queues. Snapshots, state and queue are committed back to the public repo, which gives a dated change history.

**Tech Stack:** Python 3.12, requests, beautifulsoup4, markdownify, pyyaml, feedparser, anthropic, pytest. GitHub Actions. ntfy.sh JSON publish API.

**Spec:** `docs/notifier-design.md` (read it first). Source list: `starter-list.md`.

## Global Constraints

- Repo root = `/Volumes/My Data/AI Workflow/m365-dfir-watchlist/`. Public GitHub repo.
- Levels are exactly `"push" | "digest" | "ignore"`, ordered ignore < digest < push. The AI may raise a level, never lower one set by the rules.
- Model id: `claude-haiku-5-5`. Env vars: `ANTHROPIC_API_KEY`, `NTFY_TOPIC`.
- Fetch politeness: ≥1.0 s between requests. User-Agent `m365-docs-watch/1.0`, with no personal info anywhere in requests.
- Check cron `0 */3 * * *`. Digest cron `0 13 * * 1` (08:00 EST / 09:00 EDT).
- ntfy: POST JSON to `https://ntfy.sh/` (JSON, not headers, because titles contain non-ASCII like `→`). Push priority 4, digest/info priority 3. Message body ≤ 3500 bytes.
- Ambiguous → raise the level. API failure → `digest`, or `push` if the rules fired.
- README credits Microsoft Learn (CC BY 4.0) as the source of `snapshots/`.

## Review Focus

1. **Learn returns 200 but serves an error, throttle or empty page.** Must count as a fetch failure, not "all content deleted" (which would cause a flood of pushes). Test in Task 2.
2. **Microsoft rewrites a whole page.** Hundreds of hunks must produce one classification call (input capped) and at most one alert per page. Test in Task 4.
3. **The user adds a page to `watchlist.yaml` later.** A page with no snapshot is baselined silently, with no alert. Test in Task 6.
4. **Long old/new text** must be trimmed so the ntfy body is ≤ 3500 bytes (above 4096 ntfy turns it into a file attachment). Test in Task 5.
5. **Check and digest jobs run at the same moment** and both push commits. Both workflows share `concurrency: group: repo-writes` and run `git pull --rebase` before push. Verified in Task 9.

**Interfaces:**

Flow per page, per design §5.2 and §5.5:
- no snapshot → write it, add to `baselined`, no alert
- `FetchError` → `failures += 1`; push "Page unreachable" at exactly 3
- 404, or final URL path ≠ watched path (ignoring query/fragment/case) → push "Page moved/removed"
- else diff → drop trivial hunks → none left: update snapshot silently
- else classify → push now, or queue as digest
- update snapshot and state

On the very first run (state file absent), send one push: `"Baseline complete: N pages watched"`. For pages in section "9. Change feeds", any new `learn.microsoft.com` link in added text that isn't in the watch list → queue a `{"kind":"suggestion","url":...}` item. Dry run: print what would be sent; write nothing; send nothing.
